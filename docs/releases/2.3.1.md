# bazis-bulk 2.3.1

## Fixes

- A sub-request that failed after its response had started (e.g. a streaming response)
  kept the status already sent, so an atomic bulk request committed its transaction. Such
  a sub-request gets the status 500 now (and no partial body).

## Changes

- `in_bulk_request` is a context variable (`in_bulk_request.get()`); the helpers
  `set_in_bulk_request` / `reset_in_bulk_request` are removed.
- The dispatch of `anyio.to_thread.run_sync` is installed when an atomic bulk request
  starts, not when `bazis.contrib.bulk.router` is imported.
