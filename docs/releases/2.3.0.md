# bazis-bulk 2.3.0

Requires Bazis 2.3 (Django 6.1, FastAPI 0.142).

## The dedicated thread is reimplemented

2.2 ran the sub-requests of an atomic bulk request in one thread by patching private
internals of anyio (`anyio._backends._asyncio.WorkerThread`, the thread pool context
variables) and importing `sniffio`. Current anyio releases changed these internals and
no longer depend on `sniffio`, so 2.2 fails at import, and the middleware it added
cannot be registered on a started application (Starlette 1.x).

The dedicated thread is now a single-thread executor. While an atomic bulk request runs,
a wrapper of the public `anyio.to_thread.run_sync` sends the synchronous calls made in
its context (FastAPI endpoints and dependencies) to that thread; all other calls go to
the shared pool as before. `ThreadpoolVarsPrepareMiddleware` and `threadpool_vars_prepare`
are removed. The thread closes its database connections when the request ends, and the
transaction is committed or rolled back even if the request is cancelled.

Code of a sub-request that starts an event loop of its own with `async_to_sync` (as
`RouteBase.raw_call` does) and calls synchronous code from it runs in the dedicated thread
too (through the thread-sensitive executor of asgiref), instead of waiting for the thread
that is waiting for it. Tasks started by a sub-request that outlive the bulk request use
the shared pool.

## Fixes

- An unhandled exception in a sub-request failed the whole bulk request with 500; the
  sub-request now gets the status 500 and the following ones run (in atomic mode the
  transaction is rolled back and the status is 400, as for any failed sub-request).
- The `headers` of a request item were ignored; they are now added to the headers of the
  sub-request. The `Content-Length` and `Content-Type` of the bulk request are no longer
  passed to the sub-requests: their `Content-Type` is `application/vnd.api+json` unless the
  item sets it. An item cannot set connection headers or the headers set by
  the reverse proxy (`Forwarded`, `X-Forwarded-*`, `X-Real-IP`), and values must be latin-1
  without line breaks (422).
- The `path` of a sub-request is percent-decoded, as ASGI requires (`raw_path` keeps the
  encoded form).
- A sub-request without a body received the body `null`.
- `raw_path` and an empty `query_string` were `str` instead of `bytes`, and `root_path`
  and the lifespan `state` were not passed to the sub-requests.
- A streaming sub-response made `receive` return the request again in a busy loop.
- A non-JSON response body is returned as text instead of bytes.
- `method` accepts only HTTP methods (case-insensitive); `body` can be a list.

## Limits

- A bulk request can contain at most `BAZIS_BULK_MAX_ITEMS` requests (1000 by default).
- A bulk request cannot contain bulk requests, atomic or not.

Both fail with 400 and the error code `ERR_BULK`.

CI runs the tests on Python 3.12–3.14 and with the lowest allowed dependency versions;
releases are made with the Release workflow (see `CLAUDE.md`).
